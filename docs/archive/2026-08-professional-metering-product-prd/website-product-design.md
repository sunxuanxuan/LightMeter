# FilmLightMeter 官网产品方案

## 1. 文档信息

- 产品：FilmLightMeter 配套官网
- 版本：V1.0
- 日期：2026-08-15
- 状态：实施前设计基线

## 2. 产品定位

官网是 App 的说明、分发和授权入口，不承担在线测光、社区或内容营销功能。
公开区域只提供三项核心能力：

1. 查看使用说明；
2. 下载或跳转安装最新版本；
3. 购买并获取当前设备的签名激活凭证。

App 本身完全离线。官网取得设备 ID 并确认付款后签发凭证，用户将凭证复制回
App 完成离线激活。

## 3. 目标与非目标

### 3.1 V1 目标

- 新用户可在 3 分钟内完成“下载、购买、激活”。
- 下载页始终明确展示当前版本、发布时间、系统要求和文件校验值。
- 支付成功后自动签发设备绑定凭证，重复回调不得重复签发。
- 用户关闭结果页后，可以通过订单号和购买邮箱找回凭证。
- 不建立用户账号，也不要求 App 联网。

### 3.2 V1 非目标

- 新闻、博客、社区、摄影作品展示和复杂营销落地页；
- 订阅、会员等级、团队授权和多设备授权；
- App 在线激活、在线吊销或持续联网校验；
- 公开下载未签名 APK 或裸 IPA；
- 自助换机次数管理和完整客服工单系统。

## 4. 用户与核心任务

### 4.1 新用户

需要确认 App 是否适合自己的设备，下载安装，购买授权并首次激活。

### 4.2 已购买用户

需要重新下载安装包、找回原凭证，或了解换机后的处理方式。

### 4.3 运营管理员

需要发布新版本、查看支付和签发状态、补发同设备凭证、处理换机与退款记录。
管理员能力不出现在公开导航中。

## 5. 信息架构

```text
/
└── /guide                 使用说明，默认首页
├── /download              最新安装包
├── /activate              获取激活凭证
│   └── /activate/result   支付与签发结果
├── /order/recover         凭证找回，作为激活页内入口
├── /privacy               隐私说明
├── /terms                 购买与退款说明
└── /admin                 内部运营入口，不公开导航
```

桌面端顶部导航固定显示“使用说明 / 下载 / 获取激活码”。移动端使用紧凑菜单。
“获取激活码”作为唯一强调操作。网站不设置独立营销首页，根路径直接进入使用说明。

## 6. 页面方案

## 6.1 使用说明 `/guide`

### 页面目标

让首次使用者快速完成安装、参数设置、测光与激活，并能解决常见问题。

### 内容结构

1. 快速开始：安装、授权相机、设置 ISO、选择模式、读取曝光组合；
2. 两种工作模式：专业测光与胶片预览；
3. 测光模式：平均、中央平均、中央重点、点测；
4. 激活步骤：复制设备 ID、官网购买、复制凭证、回到 App 激活；
5. 常见问题：权限、兼容性、换机、恢复出厂设置、凭证无效；
6. 隐私说明：App 不联网、不上传照片和测光数据。

### 交互

- 左侧目录或移动端章节菜单；
- 当前章节高亮；
- 图片支持点击放大；
- 顶部提供站内说明搜索，可在 V1.1 增加；
- 每个故障条目给出明确恢复动作，不展示内部技术细节。

## 6.2 下载页 `/download`

### 页面目标

只让用户获得当前可信版本，避免下载错误平台、旧包或被替换的安装包。

### Android 区域

- 当前版本号与 `versionCode`；
- 发布日期；
- 最低 Android 版本；
- APK 文件大小；
- SHA-256；
- 更新摘要；
- “下载 Android APK”主按钮；
- 安装未知来源应用的必要系统提示。

只发布经过正式签名的 Release APK。文件名使用：

```text
FilmLightMeter-<version>-android.apk
```

### iOS 区域

- 当前版本号与最低 iOS 版本；
- App Store 安装按钮，正式发布后使用；
- TestFlight 安装按钮，仅测试阶段使用；
- 审核中或暂未开放时显示明确状态。

iOS 不向公众直接提供 IPA。公开 IPA 无法形成适用于所有用户的合法安装链路，
且会绕开 App Store/TestFlight 的签名与分发规则。

### 平台识别

网站可以按 User-Agent 默认选中 Android 或 iOS，但必须允许用户手动切换。
平台识别只影响默认展示，不改变下载权限。

## 6.3 获取激活凭证 `/activate`

### 页面目标

在不建立账号、App 不联网的前提下，完成设备绑定购买与凭证交付。

### 步骤一：填写设备信息

字段：

- 平台：Android / iOS；
- 设备 ID：16 位十六进制字符；
- 购买邮箱：接收订单和找回链接；
- 已阅读购买与换机说明复选框。

输入设备 ID 时自动去除空格和连字符并转为大写。格式正确后显示分组结果，例如：

```text
A1B2 C3D4 E5F6 A7B8
```

付款前必须再次展示设备 ID，并明确提示：

> 凭证仅适用于此设备。更换设备或恢复出厂设置后需要申请重新签发。

### 步骤二：确认订单并付款

展示：

- 产品名称；
- 授权类型：单设备永久授权；
- 设备 ID 后四位；
- 价格与币种；
- 支付方式；
- 退款与离线吊销限制。

创建订单后跳转或拉起支付。支付结果以服务端回调为准，浏览器跳转结果不能作为
签发依据。

### 步骤三：获取凭证

结果页状态：

- 等待付款；
- 已付款，正在签发；
- 签发成功；
- 支付失败或取消；
- 签发异常，需要自动重试；
- 订单已退款。

签发成功后展示：

- 订单号；
- 绑定设备 ID；
- 签名激活凭证；
- 复制按钮；
- “返回 App 粘贴并激活”的下一步；
- 邮件发送状态；
- 凭证找回入口。

凭证较长，必须使用多行等宽文本区域和独立复制按钮，不能要求用户手工输入。

## 6.4 凭证找回

找回入口放在激活页底部，不增加公开导航项。

1. 用户输入订单号和购买邮箱；
2. 系统始终返回相同的模糊提示，避免泄露订单是否存在；
3. 校验通过后向购买邮箱发送一次性结果链接；
4. 链接短期有效，只展示该订单已经签发的凭证；
5. 不允许通过找回流程修改设备 ID。

## 7. 核心用户流程

### 7.1 首次安装与激活

```text
下载 App
  -> 打开 App 并复制设备 ID
  -> 官网填写设备 ID 与邮箱
  -> 确认单设备授权说明
  -> 完成支付
  -> 官网收到支付回调
  -> 签发 Ed25519 设备绑定凭证
  -> 用户复制凭证
  -> 回到 App 离线验签并保存
```

### 7.2 重新安装

用户重新下载 App。若设备 ID 未变化，可使用原凭证；若本地凭证丢失，通过订单号
和购买邮箱找回。

### 7.3 换机

V1 采用人工审核：

1. 用户提供原订单号和新设备 ID；
2. 运营核实订单、换机原因和历史处理记录；
3. 后台为新设备重新签发；
4. 原设备已保存的离线凭证无法远程吊销。

该限制必须在购买确认和换机说明中明确展示。

## 8. 异常与边界

| 场景 | 用户反馈 | 系统处理 |
|---|---|---|
| 设备 ID 格式错误 | 标记输入错误 | 不允许创建订单 |
| 支付页面关闭 | 提示可凭订单号恢复 | 后端继续等待回调 |
| 支付回调延迟 | 显示“正在确认付款” | 轮询订单状态 |
| 重复支付回调 | 无重复提示 | 幂等返回原结果 |
| 签发暂时失败 | 显示“正在重试” | 后台任务重试 |
| 邮件发送失败 | 凭证仍可复制 | 异步重试邮件 |
| 下载文件缺失 | 暂停下载按钮 | 告警并回退上一版本 |
| iOS 尚未上架 | 显示当前状态 | 不提供无效 IPA |
| 已退款订单 | 显示退款状态 | 禁止找回和重新签发 |

## 9. 视觉与交互原则

- 工具型、安静、信息密度适中，不使用大型营销 Hero 或装饰性卡片堆叠；
- 延续 App 的深色视觉，但提供系统浅色/深色自动切换；
- 内容最大宽度约 960-1120 px，说明页正文控制在易读宽度；
- 导航和主要操作位置稳定，下载与复制按钮使用清晰图标；
- 卡片圆角不超过 8 px，只用于版本项、订单摘要和错误状态；
- 状态依靠文字与图标共同表达，不只依赖颜色；
- 所有支付、下载和复制操作具备键盘访问、焦点状态和屏幕阅读器标签；
- 中文为 V1 默认语言，代码、设备 ID、版本号和校验值使用等宽字体。

## 10. 运营能力

内部管理入口至少支持：

- 发布、撤回和切换最新版本；
- 查看订单、支付回调和签发状态；
- 对同设备重新发送原凭证；
- 审核换机并签发新凭证；
- 标记退款，阻止后续找回与重新签发；
- 查看操作审计记录。

管理员必须使用独立身份认证和多因素验证。后台不与公开站点共享导航或搜索入口。

## 11. 数据与指标

V1 只记录完成业务所需的数据，不采集 App 使用行为：

- 下载次数与下载失败率；
- 创建订单数、支付成功率；
- 支付成功到凭证可复制的耗时；
- 签发失败和重试次数；
- 找回邮件成功率；
- 换机和退款数量。

禁止在分析事件、日志或错误上报中记录完整设备 ID、完整凭证和支付敏感字段。

## 12. 验收标准

1. 三个公开主功能在手机和桌面浏览器均可完整使用；
2. Android 下载按钮只指向当前正式签名 APK，并展示匹配的 SHA-256；
3. iOS 只使用 App Store 或 TestFlight 链接；
4. 未收到可信支付回调时绝不签发凭证；
5. 同一订单重复回调只产生一条有效授权记录；
6. 官网签发凭证可被 Android 和 iOS 当前版本离线验证；
7. 凭证复制、找回和邮件补发均不改变设备绑定；
8. App 无需访问官网或任何激活 API；
9. 私钥、完整凭证和支付密钥不会出现在前端包、公开日志或源码仓库；
10. 可用性和无障碍检查达到 Lighthouse 对应类别 90 分以上。

## 13. 实施优先级

### P0

- 使用说明；
- Android 下载和 iOS 安装入口；
- 订单创建、支付回调、自动签发；
- 结果页复制凭证；
- 发布与订单最小管理能力。

### P1

- 邮件交付与凭证找回；
- 换机人工审核入口；
- 下载校验值和更新记录；
- 业务监控与告警。

### P2

- 站内说明搜索；
- 多语言；
- 自助换机额度；
- 优惠码和多支付渠道。
