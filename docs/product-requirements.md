# FilmLightMeter 产品需求文档

## 1. 文档信息

- 版本：V3.0
- 日期：2026-08-20
- 状态：产品重定位基线
- 适用平台：Android、iOS
- 配套渠道：官网
- 替代文档：[已归档的专业测光产品方案](archive/2026-08-professional-metering-product-prd/README.md)

本文是 Android、iOS、官网与后续设计文档的共同产品依据。实现方案、算法细节和平台交互细节应在不违背本文目标与边界的前提下单独定义。

## 2. 产品定义

FilmLightMeter 是为非预览拍摄设备提供拍前曝光决策支持的移动应用。

用户在真实拍摄前，选择将要使用的胶片相机、底片或拍立得预设，用手机取景当前构图。冻结画面后，App 展示该预设下的成片近似结果，并给出下一步操作建议，帮助用户降低因无法预览成片带来的废片概率。

首发覆盖两类设备：

1. 一次性胶片相机：通常具有固定或极少可调的曝光参数，部分型号支持闪光灯。
2. 拍立得相机：通常由机内自动曝光决定，但可能有明暗补偿、室内/室外、闪光灯或创意档位等可操作项。

产品的核心不是模拟滤镜，也不是向用户教授或要求用户手动设置曝光三要素。它回答的是：

> 使用选中的真实设备和耗材，按当前构图拍摄，是否存在显著的曝光废片风险？现在最值得采取什么操作？

## 3. 问题与机会

胶片相机和拍立得无法在拍摄后即时确认成片。用户在室内、阴天、逆光、夜景或高反差场景中，常常无法判断：

- 固定曝光的一次性相机是否足以记录主体；
- 是否应开启闪光灯，且主体是否处于有效距离内；
- 拍立得是否应该使用明暗补偿或特定档位；
- 画面会整体偏暗、整体偏亮，还是仅主体/背景存在细节丢失风险。

现有专业测光工具要求用户理解 ISO、光圈、快门和测光方式；普通相机滤镜则无法说明真实设备能否拍好。目标用户需要的是面向设备能力的、低门槛且可执行的拍前建议。

## 4. 目标与原则

### 4.1 产品目标

1. 在用户选定真实拍摄预设后，快速给出当前构图的曝光可拍性判断。
2. 将判断转化为用户能够立刻执行的建议，例如开启闪光灯、靠近主体、切换拍立得档位、改变构图方向或暂缓拍摄。
3. 把“曝光风险判断”和“风格预览”分离；前者为首要能力，后者只作为后续增强。
4. 让用户无需理解曝光参数，也能在 30 秒内完成一次可靠的拍前判断。
5. Android 与 iOS 对同一场景、同一预设和同一操作状态给出一致的结论。

### 4.2 产品原则

- 以真实拍摄设备为中心：所有结论基于选中的相机、底片或拍立得预设，不基于用户随意修改的虚拟参数。
- 先给行动，再给解释：主界面突出一条最高优先级建议；详细 EV、参数和风险原因进入详情。
- 不确定时保守表达：无法可靠判断时必须明确说明，不输出貌似精确的结论。
- 不承诺成片：使用“风险”“预估”“建议”等措辞，不使用“保证”“真实还原”或“必出片”。
- 隐私优先：相机帧只在本机内存分析，默认不上传、不保存。

## 5. 非目标

本版本不包含：

- 专业测光模式、光圈/快门组合推荐、点测光、画幅与焦段控制等面向进阶胶片摄影的主流程；
- 将 App 变为拍照、修图、扫描、相册管理或社交分享应用；
- 像素级还原任意胶片、相纸、冲洗、扫描、镜头缺陷或环境光；
- 在没有主体距离、反射率和遮挡信息时，对闪光照明后的完整画面作精确模拟；
- 覆盖所有历史相机型号或允许用户把未验证参数标注为真实官方设备；
- 云端账号、照片上传、在线相册或行为画像。

已实现的专业测光能力可以暂时保留为内部兼容代码或调试入口，但不出现在正式用户的主导航、首启流程和官网核心文案中。

## 6. 用户与使用场景

### 6.1 目标用户

- 首次或偶尔使用一次性胶片相机的旅行、聚会和日常记录用户。
- 使用 Instax、Polaroid 等拍立得，希望减少昂贵相纸浪费的用户。
- 喜欢胶片/拍立得成像风格，但不愿学习专业曝光知识的普通摄影用户。

### 6.2 核心场景

| 场景 | 用户顾虑 | 期望建议 |
| --- | --- | --- |
| 室内人像 | 主体会不会过暗 | 开启闪光灯；靠近到有效距离；改到更亮位置 |
| 阴天户外 | 一次性相机是否仍可用 | 可以拍摄；保持稳定；避免人物处于深阴影 |
| 逆光人像 | 人脸与天空能否同时保留 | 开启闪光灯补主体；调整角度；接受背景高光风险 |
| 夜间聚会 | 是否值得按下快门 | 开启闪光灯并靠近主体；无闪光时建议暂缓拍摄 |
| 拍立得人像 | 应选亮/暗补偿还是普通档 | 切换建议的曝光补偿或场景档；保持/关闭闪光灯 |

## 7. 信息架构与核心流程

正式用户流程统一为：

```text
首次启动
  -> 相机权限说明与授权
  -> 选择设备类型
  -> 选择相机、底片或拍立得预设
  -> 实时构图评估
  -> 查看行动建议
  -> 需要时进入详情确认风险与操作原因
  -> 使用真实设备拍摄
```

App 启动后默认恢复上一次选择的预设和操作状态，直接进入实时构图评估。用户可从顶部入口更换设备或预设。

## 8. 功能需求

### 8.1 预设选择

用户必须先选择拍摄预设，才可得到针对性结论。

预设层级：

```text
设备类型
├── 一次性胶片相机
│   └── 相机型号 + 内置胶片/固定曝光配置
└── 拍立得
    └── 相机型号 + 相纸型号 + 可用操作项
```

每张预设卡至少显示：

- 品牌、型号和代表图；
- 设备类型；
- 适用耗材或内置胶片；
- 用户可操作项，例如闪光灯、亮/暗补偿、室内/室外或创意档位；
- 参数可信度与简短使用提示。

用户不能在正式预设详情中编辑固定的曝光参数。无法匹配具体型号时，可选择明确标注为“通用近似”的预设；该预设不得显示为官方型号。

### 8.2 实时构图评估

实时页面以手机相机预览作为取景参考，持续分析有效构图区域，输出以下内容：

1. 当前预设与已选择操作项。
2. 冻结按钮，用于确认当前构图并生成成片模拟。
3. 冻结后显示可拖动的原图/模拟成片分屏，左侧为手机画面，右侧为模拟成片。
4. 模拟完成后提供返回实时预览和下载模拟成片两个操作。
5. 显示一条最高优先级行动建议。

主界面禁止显示光圈、快门、EV100、红绿风险色或“欠曝/过曝”等专业术语作为主决策信息。用户应先通过左右对比理解成片差异；必要时仅以自然语言给出可执行建议。

手机自动曝光尚未稳定、相机元数据不完整或预设不可用时，必须显示“正在分析”或“暂时无法判断”，并停止提交新的拍摄建议。

### 8.3 风险与建议引擎

系统根据场景曝光、预设曝光能力、胶片/相纸宽容度、画面反差、主体优先区域及用户当前操作项，计算风险和建议。

建议必须对应用户可执行的动作。优先级如下：

1. 能显著降低风险的设备操作，例如开启闪光灯、切换亮/暗补偿或切换场景档。
2. 可改变拍摄条件的操作，例如靠近主体、改变拍摄方向、把主体移出阴影。
3. 无法避免时的明确告知，例如“背景高光可能丢失”或“当前条件下不建议拍摄”。

建议规则示例：

| 条件 | 输出建议 |
| --- | --- |
| 一次性相机环境欠曝，且闪光灯可用 | 建议开启闪光灯 |
| 闪光灯可用但主体距离超出有效范围 | 建议靠近到 `x-y m` 内 |
| 闪光灯关闭且环境适合 | 可以不使用闪光灯 |
| 拍立得支持明暗补偿且整体偏暗/亮 | 建议切换相应明暗补偿 |
| 高反差导致背景或主体有大面积风险 | 建议改变构图方向，说明主要风险区域 |
| 无可用操作能显著改善 | 当前条件下不建议拍摄 |

同一时刻只显示一条主建议；其他原因和次级建议仅在详情中显示，避免用户接收互相冲突的指令。

### 8.4 一次性胶片相机

一次性相机预设至少包含：

- 稳定 ID、版本、品牌、型号和适用地区/批次；
- 内置胶片 ISO、固定光圈、固定快门、焦距、画幅和对焦限制；
- 高光/暗部宽容度；
- 是否支持闪光灯、闪光灯有效距离和已知限制；
- 参数来源、可信度与最后核验日期。

对带闪光灯型号：

- App 必须判断并建议是否开启闪光灯。
- 用户可切换“真实相机闪光灯已开启/关闭”状态，结论随之更新。
- 用户可输入或选择主体距离区间；未提供时，仅提示距离要求，不把闪光结果当作确定结论。
- 必须说明闪光主要影响主体，背景仍主要由环境光决定。

### 8.5 拍立得

拍立得预设必须先按真实可操作能力建模，不把不同型号抽象成相同的虚拟控制。

一个拍立得预设至少包含：

- 相机型号、相纸型号、稳定 ID 和版本；
- 曝光控制特征，例如自动曝光、固定闪光、明暗补偿、室内/室外或创意档位；
- 相纸 ISO 与曝光宽容度近似参数；
- 可选操作及其对结论的影响范围；
- 参数来源、可信度与已知限制。

V1 的拍立得建议仅覆盖可明确映射到真实硬件操作的项目，例如亮/暗补偿和闪光灯状态。任何无法确认的效果必须显示为“近似建议”，不能伪装为相机内部算法的精确预测。

### 8.6 详情与冻结

用户可冻结当前稳定构图查看详情。冻结快照锁定：

- 原始分析帧；
- 场景曝光与风险结果；
- 预设 ID、预设版本和操作状态；
- 有效构图区域、时间戳和分析 revision。

冻结后显示：

- 左右分屏：左侧为冻结的手机画面，右侧为当前预设下的模拟成片；
- 可左右拖动的中间滑块，初始位置为中间；
- 模拟生成期间的明确加载状态；
- 模拟完成后的返回和下载操作；下载成功后自动恢复实时预览；
- 当前设备操作状态和一条可执行建议。

冻结状态不允许切换预设或设备操作项；用户必须恢复实时分析后再切换，防止旧帧结果被误解为新设置的实时结论。

### 8.7 风格模拟

胶片颗粒、色彩响应、暗角、相纸边框等属于后续增强，不得影响曝光结论、风险统计或建议。

当引入风格模拟时，渲染必须严格分层：

1. 曝光判断层：唯一用于风险和建议。
2. 设备/耗材响应层：用于解释亮暗压缩的近似显示。
3. 风格层：颗粒、色彩和边框等纯视觉效果。

用户关闭任意后两层时，曝光结论必须保持不变。

## 9. 结论表达与无障碍

成片对比不得只依赖颜色或术语。滑块与左右画面必须有可朗读的“手机画面”和“模拟成片”标签；操作建议必须以清晰文字呈现。

文案示例：

- “当前构图适合直接拍摄。”
- “建议开启闪光灯，并让主体保持在 1.2-3.5 m 内。”
- “画面会偏亮，建议避开强光或调整构图。”
- “画面会偏暗，建议增加现场光线后再拍摄。”
- “正在生成成片模拟。”

不得显示“曝光正确”“必定成功”“还原真实成片”等绝对表述。

## 10. 数据、隐私与权限

- 默认只请求相机权限；用户主动下载照片时，仅在 Android 8/9 请求写入公共图片目录
  所需的存储权限，Android 10 及以上通过 MediaStore 保存且不请求照片读取权限。
- 所有实时帧、冻结快照和曝光分析默认只在设备内存中处理。
- 只有用户点击“下载”后，模拟成片才会保存到本机系统相册。
- App 不上传构图、照片、设备序列号或拍摄行为。
- 崩溃和诊断日志不得包含图像像素、完整设备标识、激活凭证或预设私有来源。
- 官网只承担下载、授权和帮助内容，不承担在线分析或照片上传。

## 11. 质量与验收

### 11.1 功能验收

1. 用户可以在 30 秒内从启动完成预设选择并得到主建议。
2. 同一稳定场景、同一预设和操作状态下，重复判断的整体曝光偏差波动不超过 `0.2 EV`。
3. Android 与 iOS 使用相同测试输入时，结论、主建议和风险分类一致。
4. 闪光灯和拍立得档位建议只在对应预设支持真实操作时出现。
5. 切换预设、操作项、前后台状态或相机 session 后，旧 revision 的结论不得显示。
6. 无法可靠计算时，必须显示不可判断状态，不得保留已失效的“适合拍摄”结论。
7. 拖动对比滑块只改变可见区域，不得改变模拟结果和操作建议。
8. 每个正式预设均能追溯参数来源、可信度和核验日期。

### 11.2 性能验收

| 指标 | 目标 |
| --- | --- |
| 稳定场景下新结论更新 | 8-12 Hz |
| 预览帧率 | 正常设备不低于 24 fps |
| 画面稳定到主建议出现 | 通常 500 ms 内 |
| 冻结到详情可读 | 通常 500 ms 内 |
| 连续运行 10 分钟 | 无持续内存增长、无相机中断 |

性能不足时优先降低分析频率和预览叠层分辨率，不能改变风险阈值或伪造高置信结论。

## 12. 发布范围与路线

### V3.0 MVP

- 以“一次性胶片相机”和“拍立得”为唯一正式设备入口。
- 预设选择、实时曝光风险、主建议、风险详情和冻结。
- 一次性相机的闪光灯建议与有效距离提示。
- 至少一款已核验的一次性相机预设、一个通用近似预设和一款已核验拍立得预设。
- Android/iOS 共享预设契约和测试向量。
- 官网更新为面向非预览拍摄风险的产品说明。

### 后续版本

1. 扩充经过核验的设备、底片和相纸预设。
2. 加入主体距离输入或受支持深度能力，改进闪光主体建议。
3. 加入独立的风格模拟与可选成片近似预览。
4. 在真实设备、真实耗材和实拍样本上持续校准规则。

## 13. 遗留能力处置

现有专业测光、曝光组合推荐和双模式导航不再属于产品需求。迁移期间可保留其领域算法、相机帧分析和共享测试资产，但新功能不得依赖用户进入专业测光模式。

当新的实时构图评估覆盖正式发布路径并完成回归验证后，专业测光界面应从正式构建移除或以单独实验构建维护。旧产品需求文档已归档，仅用于追溯历史决策，不作为当前功能验收依据。
